# P0 收尾实施计划：导出能力 + 行级数据权限（RLS）

## Context

P0 首批（Excel/CSV 文件数据集 + 计算字段）已完成并验证。按用户确认，本轮补齐 P0 剩余两项：

1. **导出能力**：Excel 导出（后端已具备 xlsx 能力，但前端未接入）；PDF/图片导出（图片已有 PNG 导出，PDF 缺失）。
2. **行级权限 RLS**：现有 `data-scope.ts` 只做「记录级」数据范围（按 creatorId 过滤数据集/图表列表），没有「同一数据集内按行过滤」的能力。

目标：让管理员可为数据集配置行过滤规则（按用户/角色/部门/全员），规则在数据集执行与图表取数时自动生效；同时让数据集页可直接导出 CSV/Excel/JSON，编辑器可导出 PDF。

## 现状勘察结论

- `bi-lowcode-server/src/modules/export/export.service.ts` 已实现 `csv | json | xlsx`（exceljs），路由 `export.routes.ts` 已有 `/dataset/:id/xlsx`、`/chart/:id/xlsx`。
- 前端 `vue3-bi/src/api/export.ts` 只有 CSV/JSON 封装，且全仓库没有调用点，导出 UI 缺失。
- 编辑器已有完整 PNG 导出链路：`CanvasArea.vue` 注册 `toPng` 回调 → `stores/bi-editor/index.ts#exportCanvasAsPng` → `HeaderToolbar.vue`。后端无 PDF 依赖（无 pdfkit/puppeteer），不引入重依赖。
- `dataset.service.execute()` 是文件数据集/SQL 数据集的统一出口（图表 `chart.service.queryData` 也走它），RLS 应在此处生效。
- 缓存 key 当前为「租户 + 数据集 + limit」，加入 RLS 后必须带用户维度，否则会串数据。
- 迁移目录已到 `3_dataset_file_upload`，新迁移编号为 `4_row_permissions`；手写迁移列名必须用驼峰（仅 del_flag/created_at/updated_at 为 snake_case）。

## 实施内容

### A. 导出能力

**A1. 前端 API 封装** — `vue3-bi/src/api/export.ts`
- 新增 `exportDatasetXlsx`、`exportChartXlsx`，复用现有 `download()`。
- 新增 `exportDatasetByFormat(id, format, params)` 便捷函数（返回 Blob），供页面统一调用。

**A2. 数据集导出入口** — `vue3-bi/src/views/system/datasets.vue`
- 操作列增加「更多」下拉（原按钮保留，避免操作列继续变宽）：
  - 行级权限
  - 导出 CSV / 导出 Excel / 导出 JSON
- 处理函数调用上述 API，用现有 `saveAs(blob, filename)` 触发下载，文件名 `${row.name}_${yyyyMMdd}.${ext}`。
- 失败时 `ElMessage.error`。

**A3. PDF 导出（无新依赖，浏览器打印为 PDF）** — 
`vue3-bi/src/stores/bi-editor/index.ts` + `vue3-bi/src/views/bi-editor/components/HeaderToolbar.vue`
- store 新增 `exportCanvasAsPdf(): Promise<boolean>`：复用已注册的 PNG 回调取 dataUrl，打开新窗口写入只含标题 + 图片的打印页，`onload` 后 `window.print()`，由用户选择「另存为 PDF」。
- 弹窗被浏览器拦截时返回 false 并提示。
- HeaderToolbar 在「导出 PNG」旁新增「导出 PDF」按钮，复用 `isExportingPng` loading 状态。
- 说明：服务端 PDF 需要 Chromium 渲染，属于重依赖，本轮不做；如需后台定时导出 PDF 再单独立项。

### B. 行级权限 RLS

**B1. Prisma 模型 + 迁移**
- `bi-lowcode-server/prisma/schema.prisma` 新增：

```prisma
model RowPermission {
  id          Int      @id @default(autoincrement())
  datasetId   Int
  dataset     Dataset  @relation(fields: [datasetId], references: [id], onDelete: Cascade)
  name        String   @db.VarChar(100)
  subjectType String   @default("all") @db.VarChar(20) // all | role | user | dept
  subjectId   Int?                                     // role/user/dept ID, all 时为 null
  conditions  Json                                     // [{ field, operator, value }]
  enabled     Boolean  @default(true)
  priority    Int      @default(0)
  tenantId    Int      @default(1)
  createBy    String?  @db.VarChar(50)
  updateBy    String?  @db.VarChar(50)
  deleted     Boolean  @default(false) @map("del_flag")
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  @@map("row_permissions")
  @@index([datasetId])
  @@index([tenantId])
}
```
- `Dataset` 增加 `rowPermissions RowPermission[]`。
- 新迁移 `prisma/migrations/4_row_permissions/migration.sql`：建表 + 外键 `datasetId -> datasets.id ON DELETE CASCADE`，列名驼峰。

**B2. 纯函数工具** — 新建 `bi-lowcode-server/src/utils/row-permission.ts`
- 类型：`RowCondition { field; operator; value? }`、`RowRule`。
- 支持操作符：`eq/ne/gt/gte/lt/lte/in/notIn/like/isNull/notNull/between`。
- 占位符替换：`{userId}` `{username}` `{deptId}` `{tenantId}`；`in/between` 支持数组或逗号分隔字符串。
- 字段名白名单校验：`/^[A-Za-z0-9_\u4e00-\u9fa5]+$/`，非法直接抛参数错误（防注入）。
- `buildSqlWhereFromRules(rules, vars): { clause, values } | null`：
  - 单条规则内 conditions 为 AND，多条规则之间为 OR；
  - 列名用反引号包裹，值全部走 `?` 占位符；
  - `like` 未含 `%` 时自动包 `%value%`。
- `filterRowsByRules(rows, rules, vars)`：文件数据集内存过滤，数字优先按数值比较，空值按 `isNull/notNull` 语义处理。
- 规则应用语义：仅匹配当前用户（`all` / `role∈roleIds` / `user=userId` / `dept=deptId`）的启用规则生效；无匹配规则 = 不过滤；多规则 OR。不做管理员绕过（`all` 规则可显式覆盖全员）。

**B3. Service** — 新建 `bi-lowcode-server/src/modules/dataset/row-permission.service.ts`
- `list(datasetId)`：校验数据集存在、租户、数据范围；按 priority desc 返回。
- `create/update/remove`：校验 subjectType/subjectId/conditions；写租户与审计字段；变更后调用 `invalidateDatasetCache(tenantId, datasetId)`。
- `getOptions()`：返回当前租户下 roles/users(id,username,nickname)/departments(id,name)，供前端选择。
- `loadApplicableRules(datasetId)`：按 tenantId + deleted + enabled 查询，再按当前用户过滤；需要 dept 规则时查一次 `prisma.user.deptId`。

**B4. DTO / 路由** — `dataset.dto.ts` + `dataset.routes.ts`
- `rowPermissionSchema`：`name 1..100`、`subjectType enum`、`subjectId positive nullable`、`conditions 1..20`、`enabled`、`priority`。
- 新增：
  - `GET /api/datasets/:id/row-permissions`（`dataset:view`）
  - `GET /api/datasets/row-permission-options`（`dataset:view`）**注意放在 `/:id` 之前**
  - `POST /api/datasets/:id/row-permissions`（`dataset:edit`）
  - `PUT /api/datasets/:id/row-permissions/:ruleId`（`dataset:edit`）
  - `DELETE /api/datasets/:id/row-permissions/:ruleId`（`dataset:edit`）

**B5. execute 接入 RLS** — `dataset.service.ts`
- 缓存 key 统一追加 `:u${userId}`（从 `getRequestContext()` 取），文件/SQL 两个分支都改，防止跨用户缓存泄露。
- 文件数据集：读取 rawRows 后、`applyFieldConfig` 前调用 `filterRowsByRules`（规则引用原始字段名）。
- SQL 数据集：取数前调用 `loadApplicableRules`，若有过滤条件：
  ```sql
  SELECT * FROM ( <原 SQL> ) AS bi_rls_src WHERE (ruleA) OR (ruleB)
  ```
  values 顺序：参数占位值 → 规则值 → LIMIT 值。
- 异常信息沿用 `BizException`，日志记录命中的规则数。

**B6. 前端行级权限管理**
- `vue3-bi/src/api/dataset.ts`：新增 `RowPermission` / `RowCondition` 类型与 CRUD、options 接口。
- 新建组件 `vue3-bi/src/views/system/components/DatasetRowPermissions.vue`：
  - props: `modelValue`、`dataset: { id, name }`；
  - 规则表格（名称/适用对象/条件摘要/优先级/启用/操作）；
  - 新增/编辑弹窗：适用对象类型 + 对象选择（options），条件行（字段、操作符、值）可增删，启用、优先级；
  - 保存/删除后刷新列表并提示；关闭时 emit 刷新数据集列表。
- `datasets.vue` 接入该组件：操作列「行级权限」打开，按当前 row 传入。

## 边界与说明

- PDF 采用浏览器打印方案，不新增服务端渲染依赖；打印尺寸按画布原始像素，用户可选纸张/缩放。
- SQL 数据集的 RLS 条件作用于「原 SQL 的结果列（别名）」，规则字段需与查询输出列一致。
- 多条规则为 OR 语义，规则内多条件为 AND；无匹配规则默认不过滤（显式配置才收紧）。
- 规则变更即时失效缓存，但已打开页面需重新取数。
